# リリース前システムテストチェックリスト(FEZ-167)

実機のLINEアプリ・Webで操作し、botの返信メッセージ・画像・画面を目視で確認する。
実施(チェックの消化)は [FEZ-168](https://linear.app/fezzlk/issue/FEZ-168) で行う。

グループの操作は、実際の利用者と同じくボタン(スタートメニュー・対戦管理・設定・各画面のQuick Reply)から行う。手打ちするのは点数・チップ・場代などの数値と、ボタン導線のない操作(個人DMでの統合の起点など)だけとする。各項目の括弧内のコマンド名は、ボタンが送る内部コマンドの参考表記であり、手打ちする必要はない。

対象実装は本番未リリースの以下すべて:

- [FEZ-145](https://linear.app/fezzlk/issue/FEZ-145)(複数対戦系列の同時進行、Phase A〜F、PR #258〜#266)
- [FEZ-59](https://linear.app/fezzlk/issue/FEZ-59)/[FEZ-60](https://linear.app/fezzlk/issue/FEZ-60)(LINE↔Web連携のOAuth自動リンク方式への置き換え、PR #268)
- [FEZ-126](https://linear.app/fezzlk/issue/FEZ-126)(3人麻雀対応、PR #269)
- [FEZ-136](https://linear.app/fezzlk/issue/FEZ-136)(個人DM `_payment`/`_analysis`廃止・リッチメニュー廃止、PR #270)
- 素点一覧の貼り付けによる半荘登録(PR #272)
- [FEZ-234](https://linear.app/fezzlk/issue/FEZ-234)(グループのメニュー・ボタン配置の再設計、PR #278〜#282)
- [FEZ-137](https://linear.app/fezzlk/issue/FEZ-137)(対戦の削除・まとめて精算の実装、`_add_result`の廃止、PR #278)
- [FEZ-226](https://linear.app/fezzlk/issue/FEZ-226)(再オープン確定時の対戦状態の再検証、PR #278)
- [FEZ-225](https://linear.app/fezzlk/issue/FEZ-225)(飛び賞ボタンへの対戦・半荘IDの埋め込み、PR #283)

## 前提

- 検証用のLINEグループを2〜4人で用意する(通常の精算確認のため複数人推奨)。
- 各ケースの実行前に、対戦管理 › 戦績 › 「対戦履歴」や DB を確認し、想定外のopen対戦が残っていないことを確認してから始める。
- 「open対戦」= `status=open` のMatch。精算済みは `status=settled`。
- スタートメニューは、Botへのメンション、または精算確認の「いいえ」で再表示できる。

## 複数系列同時進行の核心

- [ ] **新規対戦の明示的な開始**: open対戦が1件もない状態で、対戦管理 › 進行中の対戦 › 「新しい対戦を始める」を押すと、グループの現在の設定(レート等)を反映した確認メッセージと「作成する」ボタンが返る
- [ ] 「作成する」を押すと新しいMatchが作成され、点数入力モードに入る(「第1回戦お疲れ様です」等の開始メッセージ)
- [ ] 既にopen対戦が1件ある状態で「新しい対戦を始める」→「作成する」を押すと、既存対戦はそのままに2件目のopen対戦が追加される(既存対戦のスコアが変化しない)
- [ ] 入力モード中(「結果を入力」を押した後、精算前)に「新しい対戦を始める」を押すと「すでに入力モードです。」等で拒否される
- [ ] **「結果を入力」のopen件数分岐 — 0件**: open対戦が0件の状態でスタートメニューの「結果を入力」を押すと、確認なしで新規対戦が作成され即座に入力が始まる
- [ ] **「結果を入力」のopen件数分岐 — 1件**: open対戦が1件の状態で「結果を入力」を押すと、ピッカーなしでその対戦の入力が始まる
- [ ] **「結果を入力」のopen件数分岐 — 2件以上**: open対戦が2件以上の状態で「結果を入力」を押すと、既存対戦一覧+「新しい対戦を始める」を含むピッカー(Quick Reply)が出る
- [ ] ピッカーから既存対戦を選ぶと、その対戦への入力が始まる(他のopen対戦には触れない)
- [ ] ピッカーから「新しい対戦を始める」を選ぶと、新規対戦が作成されて入力が始まる
- [ ] **「精算」のopen件数分岐 — 0件**: open対戦が0件の状態でスタートメニューの「精算」→「はい」を押すと「計算対象の試合が見つかりません。」が返る
- [ ] **「精算」のopen件数分岐 — 1件**: open対戦が1件なら、「精算」→「はい」でピッカーなしに即座に精算される
- [ ] **「精算」のopen件数分岐 — 2件以上**: open対戦が2件以上ある状態で「精算」→「はい」を押すとピッカーが出て、選んだ対戦だけが精算される(もう一方はopenのまま)
- [ ] 精算確認で「いいえ」を押すと精算されず、スタートメニューが表示される
- [ ] **「途中経過を確認」のopen件数分岐 — 0件**: open対戦が0件の状態で、対戦管理 › 進行中の対戦 › 「途中経過を確認」を押すと「現在進行中の対戦がありません。」が返る
- [ ] **「途中経過を確認」のopen件数分岐 — 1件**: open対戦が1件なら、ピッカーなしでその対戦の途中経過(半荘結果+グラフ)が即座に表示される
- [ ] **「途中経過を確認」のopen件数分岐 — 2件以上**: open対戦が2件以上ある状態で押すとピッカーが出て、選んだ対戦の途中経過のみが表示される
- [ ] **並行進行時の独立性**: 対戦Aで点数入力→開始メッセージの「中断する」、対戦Bで点数入力→「中断する」を交互に繰り返し、Aの半荘数・スコア・ステータスがBの操作によって変化しないことを「途中経過を確認」や「対戦履歴」で確認する
- [ ] **異なるレートの同時精算**: 「新しい対戦を始める」で対戦Aを作成→設定 › 精算ルール › 「レート」でグループのレートを変更→「新しい対戦を始める」で対戦Bを作成→両対戦にそれぞれ点数を入力し、「精算」のピッカーで個別に精算する。Aは作成時点のレート、Bは変更後のレートで精算金額が計算されていることを確認する(グループの「現在の」レートに引きずられていないこと)

## 各種ガード

- [ ] 対戦Aが入力セッション中(「結果を入力」を押した後、精算/「中断する」前)のときに、「精算」→「はい」のピッカーで対戦B(入力セッション外)を選ぶと精算がブロックされ、「現在「(Aの対戦名)」の入力中です。先に完了するか「_exit」で中断してください。」等のメッセージが返る。Bはopenのまま変化しない
- [ ] 上記ブロック後、「中断する」または対戦Aの入力完了で入力セッションを解消してから改めて対戦Bを精算すると、正常に精算できる
- [ ] 統合元グループに進行中(open)の対戦が1件でもある状態で、設定 › その他 › 「他グループへ統合」→統合先グループを選ぶと、「統合元・統合先のいずれかに進行中の対戦があるため統合できません。先に精算するか「_exit」で中断してください。」等で拒否され、統合が行われない
- [ ] 統合先グループに進行中(open)の対戦が1件でもある状態で同じ操作をしても、同様に拒否される
- [ ] 両グループのopen対戦をすべて精算/「中断する」してから「他グループへ統合」→統合先を選ぶと、統合が成功する
- [ ] 個人DM経由の統合(起点の `_personal_migrate` のみ手打ち、以降は統合元・統合先をボタンで選ぶ)でも同じガードが働く(統合元/統合先いずれかにopen対戦があると拒否される)
- [ ] 精算済みの対戦Aを、対戦履歴 › 対戦詳細 › 「この対戦を再オープン」で再オープンしたとき、別の対戦Bが並行してopen(入力セッション中)であっても、Bの入力セッション(mode/current_input_match_id)が壊れず継続できる
- [ ] 再オープンした対戦Aのレート設定を変更してから再度精算すると、変更後のレートで再精算される
- [ ] **古い再オープンボタン(FEZ-226)**: 対戦Aを「この対戦を再オープン」→再度精算した後に、会話履歴に残っている同じ「この対戦を再オープン」をもう一度押すと、「この対戦は既に別の状態になっています。」が返る。もう一度押す前の精算結果(金額)が消えていないことを、対戦詳細で確認する

## 表示

- [ ] このグループが対戦を1件しか持ったことがない(sim除く総数=1)場合、精算結果・「対戦履歴」一覧・対戦詳細のいずれにも対戦名が表示されない(従来通りの見た目)
- [ ] 対戦を2件以上持ったことがあるグループでは、精算結果に対戦名が表示される
- [ ] 同条件で「対戦履歴」の一覧表示に各対戦の名前が表示される
- [ ] 同条件で、一覧から選んだ対戦詳細の表示に対戦名が表示される
- [ ] 「途中経過を確認」の表示は上記の対戦名表示条件に関わらず、選択した対戦の半荘結果が正しく表示される

## 回帰確認(既存の単一系列フローが壊れていないこと)

- [ ] 対戦を1件も作らず(または前回精算済みの状態から)「結果を入力」→点数入力→「精算」→「はい」の一連の流れが、複数対戦対応前と同じ返信で動作する
- [ ] チップ設定(chip_rate≠0)を有効にしたグループで、通常通りチップ入力→精算が動作し、精算金額が正しい
- [ ] 飛び賞(tobi_prize)設定ありの対戦で、飛びが出た半荘の確定時に出る飛び賞ボタンで受取人を選ぶと、精算結果に正しく反映される(全員の精算金額の合計がゼロになる)
- [ ] 飛び賞メニューを押さずに点数を訂正して次の半荘へ進んだ後、前の半荘の飛び賞ボタンを押しても精算されず「入力対象が変わったため…」と返る
- [ ] (旧ボタンが残っている場合のみ)#283 リリース前に出た飛び賞ボタン(半荘IDを持たない旧形式)を押しても確定されず、同じく「入力対象が変わったため…」と返る。本番から複写した検証環境の会話履歴に旧ボタンがなければ省略してよい
- [ ] 端数計算(rounding_method)の丸めが従来通り機能する
- [ ] 対戦管理 › 進行中の対戦 › 「シミュレーション」が実系列(open対戦)のデータに影響を与えず、従来通り動作する
- [ ] ゲスト機能(設定 › メンバー › 「ゲスト」からの追加・削除)が複数対戦の状況でも従来通り動作する
- [ ] 単一対戦のみの状況でも、対戦詳細の「この対戦を再オープン」が従来通り動作する
- [ ] 途中経過の「第N回を削除」で半荘を削除する操作が、複数対戦が同時openな状況でも対象対戦の半荘だけに作用する

## 素点一覧の貼り付け登録(PR #272)

素点一覧は、点数入力時にBotが返す「名前: 点数」の一覧(または半荘削除後に届く一覧)を、そのままコピーして1メッセージで送る。

- [ ] 「結果を入力」を押さずに(待機状態で)素点一覧を貼り付けると、半荘が登録され、通常の点数入力で確定したときと同じ結果表示が返る
- [ ] open対戦が0件の状態で貼り付けると新しい対戦が作られ、1件の状態で貼り付けるとその対戦に登録されることを、「途中経過を確認」で確認する
- [ ] 「結果を入力」で入力モードに入った後(まだ点数を送っていない半荘)に貼り付けても、入力中の対戦に登録される
- [ ] open対戦が2件以上あり入力モードでない状態で貼り付けると登録されず、「入力開始から登録先の対戦を選び、素点一覧をもう一度貼り付けてください。」が返る
- [ ] 次の貼り付けでは登録されず、それぞれの理由を示す応答(末尾が「登録していません。」)が返る: 行数が人数と合わない / 未登録・同名・重複の名前を含む / 点数の合計が開始点×人数〜+99点の範囲外 / 同点のユーザーがいる
- [ ] 点数を一部だけ送った入力途中の半荘がある状態で貼り付けると、「入力途中の半荘があります。…上書きしていません。」が返り、途中の点数が消えない
- [ ] 待機状態で、「名前: 点数」形式でない普通のメッセージや1行だけの「名前: 点数」を送っても、半荘は登録されない

## LINE↔Web連携のOAuth自動リンク(FEZ-59/60)

前提: 一度も連携したことがない新規のLINEアカウント(またはテスト用に`linked_line_user_id`を空にしたWebUserがない状態)が必要。

- [ ] **新規ユーザーのOAuth登録**: Web(`/legacy/login`)の「LINE でログイン」からLINEアカウントでログインすると、未登録のため登録画面へ遷移する。名前欄はLINEの表示名がプリフィル済み(編集不可)、メールアドレス欄は空欄で手入力できる(以前は入力できないバグがあったため、実際に文字が打てることを目視確認する)
- [ ] メールアドレスを入力して「登録」を押すと、確認や承認のステップなしにログイン画面へ戻る(この画面遷移自体は仕様。以前の「Web側で承認」という手順は廃止されている)
- [ ] 続けて再度「LINE でログイン」を押すと(同じLINEアカウントで)、今度は登録済みとして認識されすぐにログインできる(プロフィールページ等、ログイン後の画面が表示される)
- [ ] ログイン後の画面(ヘッダーのドロップダウンメニュー等)が正常に描画される(**以前は削除済みページへの参照でエラーになるバグがあった**。ホーム画面・プロフィール画面の両方で確認する)
- [ ] プロフィールページに、連携したLINEアカウントの表示名が「連携済み」の状態として表示される
- [ ] 登録した名前・メールアドレスでWebUserが作成され、そのLINEアカウントが参加しているグループのデータ(対戦履歴・統計等)にWeb側からアクセスできる(認可が正しく通っている)
- [ ] LINE Bot側で個人チャットに「アカウント連携 メールアドレス」と送信しても、連携リクエストとしては処理されない(通常の呟き応答が返るのみ。**このコマンド自体を廃止したため**)

## 3人麻雀対応(FEZ-126)

- [ ] 検証用グループの設定メニュー(`_setting`、カルーセル「メンバー」→「人数」)から「3人」を選んで変更できる。変更後の設定表示で「3人麻雀」・順位点のデフォルトが `1着30/2着0/3着-30` になっていることを確認する
- [ ] 3人分の点数を入力すると(4人目を待たずに)半荘が確定する。開始点の合計が105000点前後(35000点×3人)であることを前提に、正しい組み合わせの点数で成立することを確認する
- [ ] 3人分未満(2人)で止めた状態では半荘が確定しないこと、4人目相当の入力(5人目)を試みると弾かれることを確認する
- [ ] 精算結果の金額が、3人麻雀用の開始点(35000)・返し点(40000)を前提にした計算になっていること(4人麻雀のときと異なる金額になることを、レートを揃えた上で目視確認する)
- [ ] `_setting`の「順位点」変更で、3要素(例: `30,0,-30`)を送ると正しく反映される。4要素を送るとエラーになること
- [ ] 対戦管理 › 「シミュレーション」でも3人分の入力で結果が表示されること(4人目を待たない)
- [ ] Web側の対戦編集(素点修正)でも、3人麻雀の対戦は3人分の素点で更新できること
- [ ] 人数を「3」から「4」に戻すと、4人麻雀用の順位点(元の設定)が復元される(3人用の設定を上書きして消していないこと)

## 個人DMスタブ廃止・リッチメニュー廃止(FEZ-136)

- [ ] 個人チャットで `_payment` または `_analysis` と送信すると、「開発中です」ではなく「使い方がわからない場合は〜」という未知コマンドの応答になる(コマンド自体を廃止したため)
- [ ] `_help` の応答文言に、存在しないリッチメニューのボタンへの言及がないことを確認する
- [ ] (可能であれば)一度もこのbotを友だち追加したことがないLINEアカウントで新規に友だち追加し、自己紹介メッセージは届くが、画面下部にリッチメニュー(6タイルの画像メニュー)が表示されないことを確認する。**既存の友だちには以前linkされたリッチメニューが残っている可能性があるため、必ず未フォローの新規アカウントで確認すること**

## メニュー・ボタン配置(FEZ-234)

ボタン(ButtonsTemplate / FlexCarousel)は会話履歴に残り、後から押しても動くこと。Quick Replyは直後にだけ表示されることを前提に確認する。

### スタートメニュー・対戦管理

- [ ] スタートメニューのボタンが「結果を入力 / 精算 / 対戦管理 / 設定」の順で並ぶ
- [ ] 「対戦管理」を押すと、横スクロールのカード2枚(「進行中の対戦」「戦績」)が表示される
- [ ] 「進行中の対戦」の各ボタン(途中経過を確認 / 新しい対戦を始める / シミュレーション)が、それぞれ `_active_match` / `_new_match` / `_sim` と同じ動作をする
- [ ] 「戦績」の各ボタン(成績推移 / 対戦履歴 / 累計得点表・順位表 / 個人の順位推移 / 個人の順位分布)が、それぞれ期待どおりの応答を返す
- [ ] 「累計得点表・順位表」は、メンションなしでもこのグループの対戦参加者全員が載った表になる(以前は押した人だけだった)
- [ ] 手打ちの `_history` を送ると、成績推移の対象選択(自分だけ / グループ全員 / ユーザを選ぶ)から始まる
- [ ] 数メッセージ後に、履歴に残っている古い対戦管理カルーセルのボタンを押しても動作する
- [ ] Botにメンションだけを送ると(wait モード時)スタートメニューが再表示される。点数入力中のメンションでは入力フローが中断されない

### 設定

- [ ] 「設定」を押すと、現在の設定一覧とカード3枚(「精算ルール」「メンバー」「その他」)が表示される
- [ ] 「人数」→ Quick Reply「4人」「3人」で人数を変更できる
- [ ] 「他グループへ統合」で `_migrate` の統合先選択が、「ヘルプ」で `_help` の応答が返る
- [ ] 以前の設定メニュー(「飛び賞、端数計算方法」等のボタン)が履歴に残っている場合、それを押しても新しいカルーセルが表示される

### 画面に埋め込んだボタン

- [ ] 対戦履歴の Quick Reply に、直近10件の対戦と「まとめて精算」が並ぶ
- [ ] 「まとめて精算」→ 対戦を複数選んで「合計を見る」で、選んだ対戦のプレイヤーごとの合計金額が表示される(対戦の精算状態は変わらない)
- [ ] 対戦詳細のグラフ画像に「この対戦を再オープン」「この対戦を削除」の Quick Reply が付く
- [ ] 「この対戦を再オープン」で対戦が open に戻り、スタートメニューの「結果を入力」から入力を再開できる
- [ ] 「この対戦を削除」を押すと確認(「削除する」「やめる」)が出て、この時点ではまだ削除されない。「やめる」でスタートメニューが出て対戦は残る
- [ ] 確認で「削除する」を押すと対戦が対戦履歴から消える。同じ「削除する」をもう一度押すと「見つかりません」系の応答で、別の対戦が消えたりしない
- [ ] 途中経過のグラフ画像に「第N回を削除」の Quick Reply が付き、押すと該当の半荘だけが削除される
- [ ] 半荘削除後、削除した半荘の素点が「名前: 点数」形式で届き、そのメッセージをコピーして貼り付けると同じ半荘が再登録される
- [ ] 結果入力・シミュレーションの開始メッセージに「中断する」が付き、押すと `_exit` と同じく入力が破棄される

### シミュレーション・場代

- [ ] シミュレーションの結果表示の後に、スタートメニューが再表示される
- [ ] 精算結果(グラフ画像)に「場代を入力」が付き、押して `5000` のように数字を送ると、場代込みの最終会計が表示されて通常の待機状態に戻る
- [ ] 場代入力中に数字以外を送ると「場代は自然数で入力してください。」が返り、続けて正しい数字を送れば表示される
- [ ] 場代入力中に「中断する」を押すと待機状態に戻り、精算結果は変わらない
- [ ] 他の対戦の点数入力中に「場代を入力」を押すと、開始できない旨が返り入力中の状態が壊れない
- [ ] 手打ちの `_badai 5000` も従来どおり直前の対戦に対して動作する
